# 问题：项目任务经常卡住，反复暂停且无法继续推进

报告日期：2026-11-23
报告基线：main / f712d5e
状态：待排查；本分支仅记录问题，未包含修复。

## 用户反馈

任务执行过程中经常卡住。用户继续描述任务或追问“有什么没确定，告诉我”后，仍未得到能够推进任务的明确回应。重点是执行无法持续推进，不仅是某一条提示文案。

## 截图中可确认的现象

- 用户询问“有什么没确定，告诉我”，随后可见回复“已暂停本轮任务。”
- 用户提出“建立五种范式bot，研究快速CNN”，系统回复“本轮任务的执行范围还未确认，已暂停。”
- 用户再次询问“有什么没确定，告诉我”。截图底部显示该轮“已完成，用时6秒”，但截取范围未包含其完整回复，不能据此判断该轮具体输出。
- 暂停回复上方显示“已完成”，容易让用户混淆一次模型回复结束与实际任务完成。

![用户提供的卡住现象截图](assets/repeated-task-stalls.png)

## 待验证的复现路径

1. 在项目会话中要求建立五种范式 Bot，并开展快速 CNN 相关研究。
2. 若回复因范围未确认而暂停，追问“有什么没确定，告诉我”。
3. 检查是否明确列出缺失信息或展示可操作的确认问题。
4. 补充信息后观察任务能否续接，还是继续暂停、重复询问或没有实际执行进展。

上述步骤依据用户截图整理，尚未独立复现；此前对话、模型配置、权限状态及提问卡交互未随截图提供。

## 期望行为

- 输入足够明确时推进可执行步骤；存在关键歧义时提出具体问题，而非只回复“已暂停”。
- 用户追问缺失信息时，明确说明缺什么、为何需要以及如何回答。
- 用户补充或确认后，沿用已确认信息继续任务，避免进入重复确认或暂停循环。
- 区分等待输入、执行中、阻塞、用户主动暂停和任务完成，展示下一步可采取的操作。
- 不得通过静默忽略必需确认或虚报成功来掩盖卡住问题。

## 排查线索（不是已确认根因）

`plugins/dsh-labweave-workspace/host/project-leader.js` 中存在截图对应的暂停文案。应结合实际运行日志排查：

- Leader 对范围确认、待澄清和用户主动暂停的判断是否混淆。
- 提问卡是否实际展示、回答是否被接收，确认状态是否跨轮持久化。
- 后续追问是否进入解释/续接流程，还是再次被同一执行门槛拦住。
- Bot 分派、工具错误、取消、超时等是否被统一显示成暂停，导致用户无法判断真实阻塞原因。
- UI 的“已完成”是否只代表回复结束，与项目任务状态混用。

需补充脱敏后的相关会话事件、Leader 决策和分派状态，才能确定根因。不要上传 API Key 或完整私人会话。

## 修复验收建议

- 对上述研究请求，系统能够推进任务或明确提出必要的澄清问题。
- 用户问“有什么没确定”时，得到具体缺项及可执行的答复方式。
- 回答问题后能续接，无重复创建、遗漏已完成工作或重复暂停。
- 分别覆盖信息充分、信息缺失、取消提问、工具失败和重启续接场景。
- 页面状态能够清楚区分“本轮回复结束”与“研究任务完成”。
